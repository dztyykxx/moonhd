生成时间：2026-10-12
数据源：`https://hips.china-vo.org/change2-moon-7m-dom/`（China-VO 嫦娥二号 DOM 7M，HiPS order 9，512px PNG）
测试环境：本机 `python3 -m http.server 5173`，Chromium 1306×598 视口，DPR 2（画布 2612×1196）

## 0. 本轮交付的显示策略

| 场景 | 行为 |
|---|---|
| 整球视角（底图放大倍率 < 1.0） | **只用 8K 底图**，不选瓦片、不发起任何瓦片图片请求 |
| 放大后（倍率 ≥ 1.0） | 自动接入 HiPS 瓦片，最高 **order 7**（≈28 m/像素） |
| 缩小回去（倍率 < 0.8） | 释放瓦片，平滑回到底图（滞回，避免阈值附近闪烁） |
| 瓦片未就绪 / 加载失败 | 继续显示底图，瓦片淡入；不会出现黑块或空洞 |
| 弱网 / 源站不可用 | 重试封顶 + 熔断，安静停在底图 |

**切换依据不是相机距离，而是"底图在屏幕上被放大了多少倍"**（屏幕像素 / 底图纹素）：

```
底图放大倍率 = 月球屏幕直径(设备像素) / 底图横向覆盖月球的纹素数
             = moonPx / (baseMapWidth / 2)
```

这样窗口尺寸、DPR 变化都会自动反映进来。实测（1306×598、DPR 2、8K 底图）：

| 相机距离 | 月球屏幕直径 | 放大倍率 | 细节层 |
|---|---|---|---|
| 5.25 | 863 px | 0.21 | 关 |
| 3.0 | 1573 px | 0.38 | 关 |
| 2.0 | 2567 px | 0.63 | 关 |
| 1.6 | 3556 px | 0.87 | 关 |
| 1.35 | 4889 px | 1.19 | **开**（L4） |
| 1.22 | 6329 px | 1.55 | 开（L5） |
| 1.05 | 13511 px | 3.30 | 开（L6） |
| 1.02 | 20661 px | 5.04 | 开（**L7**，封顶） |

## 1. 修掉的缺陷（全部有实测症状与验证）

### 1.1 瓦片图像坐标轴转置 —— 这就是"地图一片一片、有明显分界线"的原因

| 项目 | 内容 |
|---|---|
| 症状 | 底图与瓦片都出现明显的斜向分块边界；环形山被拉成菱形 |
| 定位 | 把同一父瓦片的 4 张 order6 子瓦片拼成面内 1024² 方块，比较接缝处与内部的差分 |
| 实测 | 接缝处相邻两行差分均值 **59.93**，是瓦片内部基准（9.36）的 **6.4 倍** |
| 根因 | 图像像素与面内局部坐标的对应搞反了：一直按 `dx=col, dy=row` 处理，正确是 **`dx=row, dy=col`**（转置）。瓦片各自被转了 90°，相邻瓦片在共享边界上对不上 |
| 独立验证 | 与本地 8K 底图逐像素相关：错误映射 r = **+0.086**；正确映射 r = **+0.679**（另两张瓦片 +0.75 / +0.80）。对 8 种二面体变换做穷举，只有"转置且不翻转"在特征明显的瓦片上都成立 |
| 修复后 | 接缝差分 **16.90**（仅为内部的 1.78 倍，残差来自瓦片间 1 像素的地理间隔） |
| 画面各向异性 | 修复前 0.751（方向性偏置，正是转置的指纹）→ 修复后 **1.000** |
| 修复 | `buildTileGrid` 改为 `tilePointVec(npix, nside, rowFrac, colFrac)`；UV 改为 u 随横向、v 随纵向；`TILE_CORNER_UV` 改为 `[[0,0],[0,1],[1,1],[1,0]]` |
| 连带 | 转置后同一索引模式的法线方向会翻面，绕向必须从 `(a,b,d)` 改成 `(a,c,d)`（实测朝外） |

### 1.2 多页图集：所有 mesh 都读第一页纹理

| 项目 | 内容 |
|---|---|
| 症状 | 瓦片数超过 64（需要第二页）时，第二页的瓦片显示的是第一页同槽位的无关内容 |
| 根因 | 图集最多两页，但 `TileLayer` 的材质始终用 `atlas.textures()[0]`；`slotUv()` 给的 uv 只在**单页内**有意义 |
| 修复 | **每页一个材质**，各自持有自己的 `tileAtlas` uniform（`detailMix/Gain/Bias` 仍共享同一对象，所以标定对所有页同步生效）；`sync()` 按 `uv.page` 选材质；`customProgramCacheKey` 带页号（否则 three 会把两页程序当同一个复用，后编译的覆盖前一个） |
| 验证 | 近距离逼出两页：第 0 页 64 张 + 第 1 页 16 张；两页 `boundTextureIsPageTexture` 均为 true；**0 个 mesh 用错材质** |
| 回归测试 | `AtlasSlots.pageOf` / 两页槽位编号独立（同一 slot 号出现在两页，必须靠 page 区分） |

### 1.3 场景过曝 —— "高清区域融不进整体画面"的真正原因

| 项目 | 内容 |
|---|---|
| 症状 | 近距离整屏发白，看不出地貌；高清区与底图都糊成一片 |
| 定位 | 用浮点 RT 读**色调映射前**的线性亮度（满月相位、曝光 1.05） |
| 实测 | 中位 0.83、p90 **1.76**、最大 **5.37**；**35.6% 的像素超过 1.0**，ACES 在 1.0 之后迅速饱和 |
| 后果 | sun=4.0 时：底图 **84%** 像素贴顶（≥254）、相邻像素梯度中位数 **0**（完全没有细节） |
| 修复 | 太阳光强度 **4.0 → 1.4**：贴顶降到 **12%**、梯度中位数升到 **9**，细节恢复 |
| 与瓦片的关系 | 不是瓦片标定不准——逐张与底图的渲染比值本来是 **0.96~1.00**；是整个场景一起过曝变白 |
| 重新标定 | 光照变了必须重算增益（ACES 非线性）：扫描得 gain 4.6→瓦片均值 151.5（底图 157.0）、gain 5.2→159.7，插值得 **gain = 5.0**，此时贴顶比例瓦片 3% / 底图 1.5% |

### 1.4 重试无限循环 + 缺熔断（弱网）

| 项目 | 内容 |
|---|---|
| 症状 | 断网时 80 张瓦片在 30 秒内打出 **1280 次请求、960 次重试** |
| 根因 | FAILED 分支直接 `cache.delete(key)`，下一次请求新建一个 `attempts=0` 的条目 → **maxRetries 永远达不到**，冷却窗口一到就再来一轮 |
| 修复 | ① 复用 FAILED 条目（保留 attempts/cooldownMs）而不是删掉重建；② 超过上限标记 `dead`，本会话不再请求；③ 新增**熔断**：连续失败 8 次暂停 60 秒；④ maxRetries 3→2 |
| 修复后 | 同样条件下 **320 次请求**（降 75%）、熔断触发 1 次、被熔断拦下 8640 次 |
| 降级表现 | 黑块 **0%**、底图正常、60 FPS、无阻塞 |

### 1.5 其他（本轮之前已修，回归测试保留）

- 三角形绕向（`gl_FrontFacing` 整块 discard）
- 几何缺 `normal` 属性（光照≈0，瓦片近黑）
- 图集纹理 `flipY=true`（每张瓦片采样到空槽位）
- 瓦片层挂在 `scene` 而非 `moon` 下（朝向错位，逐像素无变化）
- 近距离可见性判据没算瓦片自身跨度（d≤1.10 选不出瓦片）
- 亮度标定增益方向用反
- 图集重复上传（静止时 243 次/秒 → 0）
- `setPinned` 从未调用（LRU 会淘汰正在显示的瓦片）

## 4. 已知限制与未解决问题

1. **亮度标定是全局折中**：逐张所需增益在 1.9~29 之间，gain=5.0 只能取中位。
   开启细节后仍有 4%~31% 的表面像素比底图暗（最多 62 级），
   所以高清区与底图之间仍有**轻微的亮度台阶**，不是无缝的。
   要真正消除需要**逐张瓦片标定**（按底图对应区域归一化）。
2. **DOM 自带光照**：嫦娥二号 DOM 是摄影镶嵌产品，影像里已有真实阴影；
   本实现又用模拟太阳重新打光，会产生双重阴影。这是产品性质决定的，
   除非改成"不重新打光、直接把影像当自发光贴上去"（那样又会与底图的光照不一致）。
3. **7 m 影像 ≠ 7 m 地形**：地形仍来自 LOLA，本层只提供影像细节。
4. **`moc_sky_fraction=1` 是发布者声明**，本轮只抽样验证了数百张瓦片，
   不代表全月 314 万张都存在且内容正确。
5. **第一页与第二页的瓦片边界**：两页各自是 4096²，页内槽位相邻但内容无关，
   不存在跨页渗色问题（uv 有半像素内缩）；但页数上限为 2，
   超过 128 张瓦片时会出现"槽位不足"，此时按优先级保留靠屏幕中心的瓦片。
6. **改动了视觉默认值**：太阳光强度 4.0 → 1.4、亮度增益 4.558 → 5.0。
   这是为了修掉 84% 贴顶的过曝；如果更希望保留原来的高亮观感，
   可以把 `HIPS` 里的 `gain` 与 `sun` 强度一起回调，但那样近距离细节会再次糊掉。
